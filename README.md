# Student Performance — End-to-End Regression Pipeline

An end-to-end regression case study on the UCI "Student Performance" dataset
(Cortez & Silva, 2008): data understanding, EDA, preprocessing, feature
engineering, feature selection, model comparison across 9 algorithms,
hyperparameter tuning, and formal OLS regression-assumption diagnostics —
finishing in a single self-contained HTML/PDF report.

The full rendered write-up (all charts + tables inline) lives at
[`outputs/report.html`](outputs/report.html) / [`outputs/report.pdf`](outputs/report.pdf).

## Problem framing

`G3` (final grade, 0–20) is the target. Because the two earlier period grades,
`G1` and `G2`, are themselves near-perfect predictors of `G3` (r = 0.80 / 0.90),
"predict G3" is really two different problems, and both are built here:

| | Scenario A — *with prior grades* | Scenario B — *early prediction* |
|---|---|---|
| Features | Demographics + behaviour **+ G1, G2** | Demographics + behaviour only (no G1/G2) |
| Framing | "How will this student finish the year?" (mid/late semester) | "Who is at risk?" (before any grade exists) |
| Best model | Gradient Boosting | Random Forest |
| Test R² | 0.83 | 0.22 |
| Test RMSE | 1.87 | 4.01 |

Scenario B's low R² is expected, not a modeling failure — it matches the
original Cortez & Silva findings that demographic/behavioural attributes
alone explain only ~20–30% of final-grade variance. See
[Conclusions](#conclusions--recommendations) below.

## Dataset

Source: [UCI Machine Learning Repository — Student Performance](https://archive.ics.uci.edu/dataset/320/student+performance),
P. Cortez & A. Silva (2008).

- [`data/student-mat.csv`](data/student-mat.csv) — 395 students, Math course (used by this pipeline)
- [`data/student.txt`](data/student.txt) — full attribute dictionary (30 features + G1/G2/G3)
- [`data/student-merge.R`](data/student-merge.R) — original authors' R script to merge with the Portuguese-course dataset (not included here) via shared attributes

395 rows × 33 columns, 0 missing values, 0 duplicate rows. 33 students
(8.4%) scored exactly 0 on `G3`, which the source study attributes to exam
withdrawal rather than genuine failing performance — this shows up
repeatedly in the diagnostics below.

## Running the pipeline

Each script reads/writes relative paths (`../data`, `../outputs`), so run
them from inside `src/`, in this order:

```bash
cd src

# Step A/D — data understanding + EDA (writes outputs/eda_insights.json + figures 01–07)
python eda.py

# Step B/C — preprocessing, feature engineering, model selection & tuning
# (writes outputs/model_results.json + scenario figures)
python modeling.py

# Step E — OLS assumption diagnostics on Scenario A (writes
# outputs/assumptions_report.json + figures 08–10)
python assumptions.py

# Assemble everything into one HTML report (requires the three JSON files above)
python build_report.py
```

`outputs/report.html` is then a standalone file (all charts embedded as
base64) that can be opened directly in a browser or printed to PDF.

## Pipeline details

**A/D — Understanding & EDA** ([`src/eda.py`](src/eda.py)) — target
distribution, G1/G2/G3 correlation structure, full numeric correlation
heatmap, categorical breakdowns (school, sex, address, internet, romantic,
higher-ed aspiration), boxplots of key drivers (failures, studytime, goout,
alcohol use, famrel), absences vs. G3, parental education/job effects.

**B/C — Preprocessing & feature engineering** ([`src/modeling.py`](src/modeling.py)):
- 13 binary attributes mapped to 0/1; 4 nominal attributes (`Mjob`, `Fjob`,
  `reason`, `guardian`) one-hot encoded (drop-first); all numeric features
  standardized — all inside a `ColumnTransformer` fit on the train split only.
- 6 engineered features: `parent_edu_avg`, `alc_total`, `support_score`,
  `study_per_failure`, `social_score`, `log_absences` (see report for full
  rationale table).
- Feature selection via univariate F-test (`SelectKBest`) and Random Forest
  impurity importance — `failures` tops both rankings.
- 80/20 train/test split (`random_state=42`), 5-fold CV across 9 model
  families (Linear, Ridge, Lasso, ElasticNet, KNN, Decision Tree, Random
  Forest, Gradient Boosting, SVR), `GridSearchCV` tuning on the top 3 CV
  performers per scenario, evaluated once on the held-out test set.

**E — Regression assumptions** ([`src/assumptions.py`](src/assumptions.py))
— a compact, interpretable 12-feature OLS specification (`statsmodels`) of
Scenario A, checked against linearity (Rainbow test), normality (Shapiro-Wilk,
Jarque-Bera), homoscedasticity (Breusch-Pagan), multicollinearity (VIF),
independence (Durbin-Watson), and influential points (Cook's distance).

| Assumption | Test | Result |
|---|---|---|
| Linearity | Rainbow | PASS |
| Normality of residuals | Shapiro-Wilk | FAIL |
| Homoscedasticity | Breusch-Pagan | FAIL |
| No multicollinearity | max VIF (~4.0) | PASS |
| Independence of errors | Durbin-Watson (~2) | OK |
| Influential points | Cook's distance > 4/n | flagged |

Both failures trace back to the zero-grade dropout group — excluding those
students raises R² from 0.82 to 0.94 and substantially improves (though does
not fully fix) both test p-values. See `outputs/report.html` for the full
diagnostic plots and the recommended two-stage "hurdle" model (dropout
classifier + regression on completers).

## Conclusions & recommendations

1. **Report both scenarios, never one number.** Scenario A (R² ≈ 0.83) and
   Scenario B (R² ≈ 0.22) answer genuinely different questions.
2. **Tree ensembles win in both framings** (Gradient Boosting / Random
   Forest beat every linear and instance-based model after tuning),
   indicating non-linear/interaction effects in the data.
3. **`failures` is the most decision-relevant lever** available before any
   grade exists; `study_per_failure`, absences, and parental education add
   secondary signal.
4. **The zero-grade dropout group should be modeled separately** — it drives
   the OLS normality/heteroscedasticity failures and a visible cluster of
   high-Cook's-distance points.
5. **Next steps:** replicate on `student-por.csv` / the 382-student merged
   panel to test generalization; add interaction terms (`failures ×
   studytime`); try quantile regression to characterize the at-risk tail
   directly.

`random_state=42` is fixed throughout (train/test split, CV folds, all
